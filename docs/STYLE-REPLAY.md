# 辐射76群聊风格 v0.4.0：本机回放

语料为用户在会话中贴出的 11 月 10 日两段 QQ 聊天节选，替换了发送者标识，在临时目录离线运行。没有接入完整 Windows 历史；没有把聊天原文、账号、图片、临时 SQLite 或真实人设装入发布包。

| 检查 | 学习前 | 学习后 |
| --- | --- | --- |
| 采集和来源 | 0 个样本 | 31 条转录中 25 个进入风格库，22 个有合格对话关联；机器人输出和识别出的直接问机器人片段排除 |
| 风格版本 | 0，无风格 | 1，自动应用；记录了 5 项差异与来源 |
| 给模型的风格 | 没有额外风格段 | 192 字符，且只有一段 |
| 固定人设、既有记忆、GCP 回复指令 | 存在 | 全部保留；移除风格段后系统内容相同，原群上下文和问题仍由 GCP 恢复 |
| 事实知识、预算、发送 | 不变 | 无知识写入、无模型 API 请求、无 QQ 发送 |

学到的内容：日常先用短句讲重点，随口接话少用句号，没把握就标明，遇到图片用文字简短接住，闲聊优先响应武器与配装。截图占位符只用于判断图片反应，无法辨认图中内容；转录没有引用 ID，回放标记为相邻对话，不冒充精确引用。原聊天里的四星词条数值与任务奖励说法没有进入生成请求或知识库。这小段不足以为接梗、认错等全部维度提供证据；这些维度及精确引用、明确表情包标识用合成用例验证。

对同一个问题，观察到的变化是模型请求多了可审计的表达规则。例如「四星暴怒怎么查？」原请求只含既有人设和上下文，学习后多了「平常先用短句讲重点……没把握时直说不确定，措辞不代替查证」。没有调用生成模型，因此这里展示的是实际请求差异，不是生成质量或词条数值的验证。

本机用 [group_chat_plus aa97e0e](https://github.com/Him666233/astrbot_plugin_group_chat_plus/commit/aa97e0e35a18733e73db753238dd2a3021446e42) 的实际 `on_llm_request` 重写方法和 [AstrBot faba6c0](https://github.com/AstrBotDevs/AstrBot/commit/faba6c02d2e385befb04afadc8023372fe63971a) 的原生系统消息组装语句离线验证。真实宿主、网络、工具、模型和发送接口均未启动。公开上游普通群回复链已通过；Windows 实装版本、补丁和真实历史需按安装说明验收。
